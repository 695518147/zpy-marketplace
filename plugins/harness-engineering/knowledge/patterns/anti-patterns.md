# Anti-Patterns — 反模式

本文档记录常见的反模式，供 Harness 识别和避免。

---

## 代码反模式

### 1. 上帝类 (God Class)
一个类承担过多职责，导致难以维护。

**识别特征**：
- 类超过 1000 行
- 方法超过 50 个
- 类名包含 Manager/Handler/Service

**解决方案**：
- 拆分职责
- 使用策略模式
- 提取子类

### 2. 循环依赖 (Circular Dependency)
模块之间相互依赖，形成闭环。

**识别特征**：
- A → B → C → A
- 编译时报循环依赖错误

**解决方案**：
- 依赖倒置
- 提取公共接口
- 重新设计模块边界

### 3. 硬编码 (Hard Code)
在代码中直接写入配置值。

**识别特征**：
- 代码中出现魔法数字
- 字符串直写

**解决方案**：
- 提取到配置文件
- 使用环境变量
- 放入常量类

## 设计反模式

### 4. 需求跳跃 (Requirement Skip)
未经设计直接实现功能。

**特征**：
- 没有 spec 文件
- 直接写代码
- 返工频繁

**Harness 强制**：
- HARD GATE: 必须先 brainstorming 并得到用户 approved

### 5. 复制粘贴编程 (Copy-Paste Programming)
复制现有代码修改，不提取公共逻辑。

**特征**：
- 代码重复率 > 20%
- 修改需要改多处

**解决方案**：
- 提取公共方法
- 使用继承或组合
- 重构为模板方法模式

---

## 测试反模式

### 6. Mock 过度 (Over-mocking)
过度使用 mock 导致测试失去意义。

**特征**：
- 测试只验证 mock 调用
- 不验证真实业务逻辑

**解决方案**：
- 使用真实对象测试
- 只 mock 外部依赖
- 添加少量关键 mock

### 7. 测试跳过 (Test Skip)
遇到失败就跳过测试。

**特征**：
- 有 @Ignore 注释
- 测试被注释掉

**Harness 强制**：
- 测试覆盖率 < 80% 禁止合并
